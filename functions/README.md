# COIL Cloud Functions

Firebase Cloud Functions backend for the COIL iOS app (TypeScript, Node 22).

Every AI call the app makes goes through here — the iOS client never talks to
Anthropic, OpenAI, Gemini or BFL directly, and never holds a provider API key.
System prompts and model configuration are **server-side** (`src/prompts.ts`),
so prompt changes ship with a function deploy rather than an App Store release.
The proxy also owns the safety envelope: per-user rate limiting, a per-user
daily quota, a global daily spend ceiling, request-type allow-listing, age /
consent eligibility checks, and Zod validation of every AI response before it
reaches the client.

Firebase project: **`pt-helper-dev`** (see `../.firebaserc`). Emulator project
id: **`demo-coil`**.

## Deployed functions

Derived from `grep '^export const' src/index.ts` plus the re-exports at the top
of `src/index.ts`. Everything listed here is deployed by `npm run deploy`.

| Function | Trigger | Purpose |
|---|---|---|
| `claudeProxy` | HTTP | Main AI proxy — routes the 9 client request types to Claude with rate limiting, quota, eligibility and response-schema validation |
| `crossVerify` | HTTP | Cross-model fact-check of rehab-plan exercises via `gpt-4o-mini` |
| `deleteAccount` | HTTP | Deletes all server-side data for the caller, then the Auth user (Auth last, every step idempotent) |
| `createVirtualUserToken` | HTTP | Mints Firebase custom tokens for `vuser-` test identities; hard-restricted to `pt-helper-dev` |
| `agentInsights` | HTTP | Managed Agent producing the recovery-insights digest; falls back to the single-call path on failure |
| `agentFormAnalysis` | HTTP | Managed Agent comparing the current form session against prior sessions of the same exercise; falls back to the single-call `form_analysis` path |
| `generateExerciseImage` | HTTP | On-demand exercise illustration: mapping lookup, FLUX generation, Gemini QA gate, Storage upload |
| `backfillAnalytics` | HTTP (admin) | Re-materializes GA4 days on demand — the same-day verification path for the analytics pipeline |
| `dashboardData` | HTTP (admin) | Read API for the monitoring dashboard; serves from Firestore only, never BigQuery |
| `onBudgetAlert` | Pub/Sub (`budget-alerts`) | Hard billing shutoff at 120% of budget; dry-run unless `BILLING_SHUTOFF_ENABLED=true` |
| `aggregateDailyMetrics` | Scheduled (daily 01:00 UTC) | Behavioral counts into `analytics/dailyAggregates/{date}` — no health data |
| `sendNightlyReport` | Scheduled (daily 07:00 Asia/Jerusalem) | Claude-written product analytics digest, structurally validated then emailed via SendGrid |
| `pullDailyAnalytics` | Scheduled (daily 17:00 UTC) | BigQuery → Firestore materialization of the GA4 export (re-pulls the last 2 days; GA4 restates shards for ~72h) |

`dashboardData` is also reachable at `/api/dashboard` through the Hosting
rewrite in `../firebase.json`.

## Source map (`src/`)

| File | What it is |
|---|---|
| `src/index.ts` | HTTP + scheduled handlers, Firestore-backed rate limiter, per-user quota, global daily spend ceiling, eligibility gate, nightly-report assembly |
| **`src/prompts.ts`** | **`SYSTEM_PROMPTS` and `MODEL_CONFIG` live here** — the server-side prompt text and per-request-type model settings. Side-effect-free by design |
| `src/response-schemas.ts` | Zod schemas, one per AI request type; pinned to `../contracts/response-schemas/`. A failed parse returns 502 rather than passing a malformed payload to iOS |
| `src/managed-agent.ts` | Managed Agents client for recovery insights (`submit_recovery_insights` tool) |
| `src/form-agent.ts` | Managed Agents client for cross-session form analysis (`submit_form_analysis` tool) |
| `src/firestore-queries.ts` | Server-side recovery data assembly (14-day window) + sanitization of free text before it enters agent prompts |
| `src/image-generation.ts` | On-demand exercise image pipeline behind `generateExerciseImage` |
| `src/analytics-pull.ts` | BigQuery reads and the Firestore documents the dashboard renders |
| `src/dashboard-data.ts` | Dashboard read paths and the `requireAdmin` gate (owns the Firestore path constants) |
| `src/ai-usage.ts` | Per-call usage/cost telemetry; never records a uid or user content, never throws into a response path |
| `src/ai-pricing.ts` | Static provider price table and cost math; unknown model → `null`, never a guess |
| `src/nightly-report-validator.ts` | Structural check on the Claude-generated report markdown before it is emailed |
| `src/billing-shutoff.ts` | Budget-alert handler that disables project billing |
| `src/account-deletion.ts` | Firestore-side account deletion, extracted so it can run against the emulator |
| `src/logger.ts` | Request-scoped structured logging to Cloud Logging |
| `src/generated/exerciseCatalog.ts` | **Tracked build output.** Regenerated by every build from the image mapping — never hand-edit it |

## Build & test

Run everything from this directory.

```bash
npm ci                  # install (CI uses this; lockfile is authoritative)
npm run lint            # eslint over src/ only
npm run build           # prebuild codegen + tsc → lib/
npm test                # jest unit suite, no emulator needed
npm run test:rules      # Firestore security rules (emulator)
npm run test:integration # integration suite (emulator)
npm run serve           # build + local functions emulator
npm run deploy          # build + firebase deploy --only functions
```

Notes:

- `npm run build` fires a `prebuild` hook that regenerates
  `src/generated/exerciseCatalog.ts` from
  `../scripts/output/exercise_image_mapping.json`. That path is a **hard
  dependency of the build** — do not move or rename that file. The generated
  file is committed, so a build should leave it byte-identical unless the
  mapping actually changed.
- `npm run lint` lints `src` only. `scripts/`, `test/`, `lib/` and
  `src/generated/` are ignored (`eslint.config.js`).
- `npm test` uses `jest.config.js` and matches `test/**/*.test.ts`.
  `test:rules` and `test:integration` wrap jest in
  `firebase emulators:exec --project demo-coil` and additionally need **Java 21**
  and `firebase-tools` installed.
- **Never run `npm run deploy` from two sessions at once** — there is a single
  `pt-helper-dev` project and concurrent deploys clobber each other.

## One-off scripts (`scripts/`)

These are run with `ts-node`. `tsconfig.json` has `"include": ["src"]`, so
nothing in `scripts/` is compiled into `lib/` or shipped in the deploy bundle.

| Script | How to run |
|---|---|
| `scripts/build_catalog.ts` | automatic — the `prebuild` hook |
| `scripts/setup-managed-agent.ts` | `npm run setup-agent` — one-time creation of the recovery-insights agent + environment |
| `scripts/setup-form-agent.ts` | `npm run setup-form-agent` — one-time creation of the form-analysis agent (reuses the existing environment) |
| `scripts/test-agent-e2e.ts` | `npx ts-node scripts/test-agent-e2e.ts` — live end-to-end exercise of `agentInsights` against dev |

Both setup scripts print IDs that must then be stored as Firebase secrets
(`MANAGED_AGENT_ID`, `MANAGED_ENVIRONMENT_ID`, `FORM_AGENT_ID`).
